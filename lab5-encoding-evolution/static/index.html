DDIA Interactive Playground (All 12 Chapters) สนามทดลองตามไฟล์สรุปภาษาไทย Designing Data-Intensive Applications ครบทั้ง 12 บท

กดเลือกบทที่ต้องการทดลองเล่นได้เลย (บทที่ 1 ถึง บทที่ 12 — ไม่ต้องเปิด Docker!)

🪪 การทดลองที่ 1 (ตอนที่ 2 หน้า 1–3): โปรไฟล์ LinkedIn — โมเดลเอกสาร (JSON) ปะทะ โมเดลเชิงสัมพันธ์ (ตาราง SQL)

กดปุ่มทั้ง 3 สถานการณ์ด้านขวา เพื่อดูว่าเมื่อไหร่แบบเอกสาร (JSON ต้นไม้) ดีกว่า และเมื่อไหร่แบบตาราง (Relational) ชนะขาด!

🦈 การทดลองที่ 2 (ตอนที่ 3 หน้า 3–4): นับจำนวน "ฉลาม" รายเดือน

เปรียบเทียบการสั่งงานคอมพิวเตอร์ 3 แนวคิด: สั่งทีละขั้น (Imperative) vs MapReduce vs บอกแค่ผลลัพธ์ที่ต้องการ (Declarative SQL)

🕸️ การทดลองที่ 3 (ตอนที่ 4 หน้า 4–6): โมเดลกราฟ "ลูซี่ (Lucy) กับ อแลง (Alain)"

ทำไมข้อมูลที่เชื่อมโยงกันซับซ้อนหลายชั้น (เมือง ──► รัฐ ──► ประเทศ ──► ทวีป) ใช้ภาษา Cypher แค่ 4 บรรทัด แต่ถ้าใช้ SQL ต้องเขียนถึง 29 บรรทัด?

แผนภาพจุด (Vertex) และเส้นเชื่อม (Edge) ในหนังสือหน้า 5:
👩 [ลูซี่ (Lucy)] ──(เกิดที่)──► [รัฐไอดาโฮ] ──(อยู่ใน)──► [สหรัฐอเมริกา (USA)] ──(อยู่ใน)──► [อเมริกาเหนือ]
👩 [ลูซี่ (Lucy)] ──(อาศัยอยู่ที่)──► [ลอนดอน] ──(อยู่ใน)──► [อังกฤษ] ──(อยู่ใน)──► [ทวีปยุโรป (Europe)]
💑 [ลูซี่ (Lucy)] ◄──(แต่งงานกับ)──► 👨 [อแลง (Alain)] ──(เกิดที่)──► [ฝรั่งเศส] ──(อยู่ใน)──► [ทวีปยุโรป]

📼 การทดลองที่ 1 (ตอนที่ 2–3 หน้า 1–2): ฐานข้อมูลที่ง่ายที่สุดในโลก & ดัชนีแบบแฮช (Bitcask Hash Index + Compaction)

ลองกดเขียนยอดวิววิดีโอต่อท้ายไฟล์ (Append-only Log), กดลบด้วยป้ายหลุมศพ (Tombstone), แล้วกดบีบอัดรวมไฟล์ (Compaction)!

🌲 การทดลองที่ 2 (ตอนที่ 4–6 หน้า 2–5): ศึกชิงเจ้าระบบจัดเก็บ — LSM-Tree ปะทะ B-Tree

กดเลือกสถานการณ์เพื่อเปรียบเทียบกลไกเบื้องหลังระหว่าง LSM-Tree (Memtable + SSTable + Bloom Filter) กับ B-Tree (หน้าขนาดคงที่ 4 KB + WAL)

📊 การทดลองที่ 3 (ตอนที่ 8–9 หน้า 6–8): งานวิเคราะห์ (OLAP) & การบีบอัดแบบคอลัมน์ (Bitmap + RLE)

ทำไมคลังข้อมูล (Data Warehouse / Star Schema) ถึงแยกเก็บข้อมูลทีละคอลัมน์ แล้วบีบอัดด้วย Bitmap Encoding + Run-Length Encoding (RLE)?

🔬 การทดลองที่ 1: ผ่าดูขนาดไบต์จริง (ตอนที่ 3 – ตอนที่ 7: ทำไม JSON ถึง 81 ไบต์ แต่ Avro เหลือแค่ 32 ไบต์?)

ข้อมูลตัวอย่าง 3 ชนิด: ข้อความ ("Martin"), ตัวเลข (1337), และอาเรย์ (["daydreaming", "hacking"])

🔍 ผ่าไบต์ Protocol Buffers (33 ไบต์) — ใช้หมายเลขประจำช่อง (Field Tag #1, #2, #3)
👑 ผ่าไบต์ Apache Avro (32 ไบต์) — ไม่มีทั้งชื่อช่องและไม่มีหมายเลข Field Tag!

🔄 การทดลองที่ 2: จำลอง Rolling Upgrade (ความเข้ากันได้ย้อนหลัง Backward vs ไปข้างหน้า Forward)

กดเลือกสถานการณ์ด้านล่างเพื่อทดสอบว่าเมื่อโค้ดเก่า (v1) และโค้ดใหม่ (v2) ทำงานพร้อมกันในระบบ แบบไหนรอด แบบไหนพัง!

🪤 การทดลองที่ 3: กับดักฐานข้อมูล (ตอนที่ 8 หน้า 5)

โค้ดใหม่ (v2) เขียนช่องใหม่ 4:loyaltyPoints = 500 ลงฐานข้อมูลไว้ ต่อมาโค้ดเก่า (v1) อ่านแถวนี้ขึ้นมาแก้ค่าอื่นแล้วเขียนกลับลงไป!

ข้อมูลที่อยู่ในฐานข้อมูลตอนนี้: 

          


          

        

      

    

  


  
  
  
  


    
    

      

        

          

            👑 การทดลองที่ 1 (ตอนที่ 2–4 หน้า 1–3): แบบมีผู้นำคนเดียว (Single-Leader) & กับดักตอนเปลี่ยนผู้นำ (GitHub Failover / Split Brain)
          

          

            กดเลือกสถานการณ์ด้านขวาเพื่อดูการทำงานแบบกึ่งรอ (Semi-Synchronous), เหตุการณ์จริงที่ GitHub ข้อมูลรั่วตอนเปลี่ยนผู้นำ, และภาวะสมองแยก (Split Brain)!
          

        


        

          
          
          
        

      


      

    


    
    

      
      

        

          

            👻 การทดลองที่ 2 (ตอนที่ 5 หน้า 3–4): 3 อาการหลอนเมื่อสำเนาตามไม่ทัน (Replication Lag)
          

          

            เมื่อใช้แบบไม่รอ (Asynchronous) แล้วสำเนาล้าหลัง ผู้ใช้จะเจอเรื่องแปลกๆ 3 แบบ กดดูแต่ละอาการและวิธีแก้ได้เลย!
          


          

            
            
            
          


          

        

      


      
      

        

          

            🛒 การทดลองที่ 3 (ตอนที่ 7–8 หน้า 5–7): แบบไม่มีผู้นำ (Dynamo Quorum) & ตะกร้าสินค้า "นม + ไข่"
          

          

            ทดสอบกฎเสียงข้างมาก (w + r > n), การฝากข้อมูลไว้โซฟาเพื่อนบ้าน (Sloppy Quorum), และการรวมตะกร้าสินค้าด้วยหมายเลขเวอร์ชัน (Sibling)!
          


          

            
            
            
            
          


          

        

      

    

  


  
  
  
  


    
    

      

        

          

            💥 การทดลองที่ 1 (ตอนที่ 3 หน้า 2): ผ่า 4 ปัญหาข้อมูลตีกันเมื่อทำงานพร้อมกัน (Race Conditions)
          

          

            กดเลือกเหตุการณ์จากในหนังสือด้านขวา: โอนเงิน 2 บัญชีแล้วเห็นเงินเหลือ 900 บาท, พนักงานบวกเลขทับกัน, และ หมอเวร 2 คนกดขอลาหยุดพร้อมกัน!
          

        


        

          
          
          
          
        

      


      

    


    
    

      
      

        

          

            🛡️ การทดลองที่ 2 (ตอนที่ 4 หน้า 2–3): ระดับการแยกธุรกรรม (Isolation Levels) & กลไก MVCC
          

          

            กดสลับระดับการป้องกันเพื่อดูว่าแต่ละระดับกันปัญหาไหนได้บ้าง และทำไม Snapshot Isolation (MVCC) ถึงยังกันเคสหมอเวรลาหยุดพร้อมกันไม่ได้!
          


          

            
            
            
          


          

        

      


      
      

        

          

            ⚙️ การทดลองที่ 3 (ตอนที่ 5 หน้า 3–4): 3 วิธีไปให้ถึงระดับสูงสุด Serializable
          

          

            เปรียบเทียบการรันทีละคำสั่งบนเธรดเดียว (Redis/VoltDB), การล็อกสองขั้นตอน (2PL — เสี่ยงติดล็อกตายหมู่ Deadlock), และการตรวจจับแบบใจดี (SSI)!
          


          

            
            
            
          


          

        

      

    

  


  
  
  
  


    
    

      

        

          

            🌐 การทดลองที่ 1 (ตอนที่ 2 หน้า 1–2): ความผิดพลาดของเครือข่าย, การตั้งเวลารอ (Timeout) & การตัดเงินซ้ำสองรอบ vs Idempotence
          

          

            กดเลือกสถานการณ์ด้านขวาเพื่อดูว่าทำไมการส่งซ้ำหลังหมดเวลา (Timeout + Retry) ถึงทำให้ลูกค้าโดนตัดเงินสองรอบ และวิธีแก้ด้วยคำสั่งแบบ Idempotence!
          

        


        

          
          
          
        

      


      

    


    
    

      
      

        

          

            ⏰ การทดลองที่ 2 (ตอนที่ 3 หน้า 2): นาฬิกาที่ไม่เคยตรงกัน (Clock Skew) vs Google Spanner
          

          

            จำลองเหตุการณ์ในหนังสือ: เมื่อนาฬิกา เครื่อง B เดินเร็วกว่าความจริงไป 2 วินาที (12:00:02 vs 12:00:01) ทำไมข้อมูลใหม่กว่าของเครื่อง A ถึงถูกลบทิ้งเมื่อใช้ Last Write Wins (LWW)?
          


          

            
            
          


          

        

      


      
      

        

          

            🗳️ การทดลองที่ 3 (ตอนที่ 4–5 หน้า 3–4): เมื่อคอมพิวเตอร์ต้องโหวตหาความจริง (Quorum & Consensus)
          

          

            เมื่อเครือข่ายขาดกลางคันแบ่งระบบเป็น ฝั่งซ้าย 2 เครื่อง กับ ฝั่งขวา 3 เครื่อง อัลกอริทึม Paxos / Raft / Zab ป้องกันการมีผู้ใหญ่บ้าน 2 คนพร้อมกันอย่างไร?
          


          

            
            
          


          

        

      

    

  


  
  
  
  

    

      

        

          

            🏛️ บทที่ 1: ระบบที่เชื่อถือได้ ขยายได้ และดูแลง่าย (Twitter ไทม์ไลน์ / เปอร์เซ็นไทล์ p99.9 Amazon / Chaos Monkey)
          

          

            กดปุ่มด้านขวาเพื่อดูการแก้ปัญหาไทม์ไลน์คนดังของ Twitter, เหตุผลที่ Amazon แคร์เปอร์เซ็นไทล์ที่ 99.9, และ 3 เสาหลักของระบบข้อมูล!
          

        

        

          
          
          
        

      

      

    

  


  
  
  
  

    

      

        

          

            🧩 บทที่ 6: การแบ่งข้อมูลเป็นส่วน ๆ (Key Range vs Hash / ดัชนีรถมือสองสีแดง / Rebalancing & ZooKeeper)
          

          

            กดปุ่มด้านขวาเพื่อดูวิธีแบ่งข้อมูลหลีกเลี่ยงจุดร้อน (Hot Spot), การค้นหารถสีแดงด้วย Local vs Global Index, และทำไมห้ามใช้ hash % N!
          

        

        

          
          
          
        

      

      

    

  


  
  
  
  

    

      

        

          

            🌊 บทที่ 9: การประมวลผลสตรีม (Kafka Event Log / CDC & Event Sourcing / ซื้อของ 12:59 น. เน็ตหลุด / Stream Joins)
          

          

            กดปุ่มด้านขวาเพื่อดูความต่างของคิวข้อความกับ Event Log, ปัญหาเวลา Event Time vs Processing Time (Watermarks), และการเชื่อมสตรีมค้นหารองเท้า!
          

        

        

          
          
          
        

      

      

    

  


  
  
  
  

    

      

        

          

            🏭 บทที่ 10: การประมวลผลแบบแบตช์ (ปรัชญา Unix Pipes ──► MapReduce & HDFS ──► Apache Spark DAG)
          

          

            กดปุ่มด้านขวาเพื่อดูวิวัฒนาการจากท่อคำสั่ง Unix สู่ MapReduce และทำไมยุคใหม่ถึงเปลี่ยนมาประมวลผลในหน่วยความจำด้วย Dataflow Engines (Spark)!
          

        

        

          
          
        

      

      

    

  


  
  
  
  

    

      

        

          

            🔗 บทที่ 11: การประมวลผลสตรีมมิ่งแบบปลายทางถึงปลายทาง (Checkpoints / ไม่ตัดเงินเบิ้ล / Lambda สู่ Unified)
          

          

            กดปุ่มด้านขวาเพื่อดูว่าทำไมเครื่องแฮงก์กลางคันแล้วข้อมูลไม่หาย ยอดเงินไม่ถูกบวกเบิ้ล (End-to-End Exactly-Once) และจุดจบของ Lambda Architecture!
          

        

        

          
          
        

      

      

    

  


  
  
  
  

    

      

        

          

            🚀 บทที่ 12: อนาคตของระบบข้อมูล (อวสานฐานข้อมูลครอบจักรวาล / Unbundling เลโก้ / สิทธิในการถูกลืม & จริยธรรม)
          

          

            กดปุ่มด้านขวาเพื่อดูการร้อยเรียง PostgreSQL + Elasticsearch + Redis + Parquet ด้วย CDC และการแยกชิ้นส่วนฐานข้อมูลมาต่อเหมือนเลโก้!
